# Keiba Analyzer — 競馬予想AI（開発中）

> 競馬予想に含まれる感覚的な判断を、再現可能なデータ処理・能力評価・信頼度管理へ落とし込む個人開発プロジェクトです。

**現在開発中です。** データ基盤、説明可能な能力評価、馬場分析、区間展開・隊列予測、位置別能力要求、直線到達までを一つの予想エンジンへ接続しています。

本リポジトリは採用ポートフォリオ向けの公開版です。Private版から、個人情報・認証情報・収集済みデータ・外部サイト固有の取得処理を除外し、設計と代表ロジックが伝わる形に再構成しています。

## 3分で確認できるポイント

1. [`docs/architecture.md`](docs/architecture.md) — データ収集から評価までの全体設計

4. [`src/keiba_analyzer/scoring/lap_based_leader.py`](src/keiba_analyzer/scoring/lap_based_leader.py) — 逃げられる速さと逃げる傾向を分ける代表実装
5. [`database/analysis_schema.sql`](database/analysis_schema.sql) / [`tests`](tests) — 再現可能な保存設計と単体テスト

## 解決したい課題

競馬予想では、馬場、展開、追走力、最高速度、スタミナなど多くの要素が絡み、判断基準が曖昧になりやすいという課題があります。そこで、次の流れを一つの分析基盤として構築しています。

- 2020年以降の中央競馬全レースを収集対象としてデータを蓄積
- 出走情報、過去走、通過順、上がり3F、レースラップ、個別ラップを正規化
- 馬の主要能力と補助適性を分離し、各過去走を0〜10点で評価
- 欠損データを無理に平均値で埋めず、信頼度と評価状態を併記
- 採点根拠を保存し、結果を後から検証できるようにする
- 当日の馬場、区間展開、予想隊列から馬ごとに異なる能力配分を生成
- 4角位置と残存余力だけでなく、直線で実際に追い抜けるかを計算
- 能力ロジックごとの入力指紋で、変更のあった能力だけを安全に再計算
- ログイン単位で状態を分離し、複数レースの予想ジョブを並行実行

## 能力評価の設計

主要能力は次の5項目です。

| 項目 | 評価の主眼 |
|---|---|
| 基礎スピード | 巡航速度と追走力 |
| 最高速度 | 終盤で到達できる速度 |
| ギアチェンジ | 短い区間で急加速する力 |
| ロングスパート | 高い速度を長い区間維持する力 |
| スタミナ | ペース・距離・位置による消耗後も速度を残す力 |

補助適性として、低グリップ適性、坂適性、重馬場適性、小回り適性、持ち時計上限を使います。1200mではロングスパートの代わりにスプリント性能を使用します。

公開版では、**基礎スピード**、**最高速度の発揮モデル**、**逃げ馬判定**、**馬場・展開・位置別能力要求**の代表ロジックを、外部データやPrivate版のDBに依存しない形で掲載しています。

## 直近の設計更新

- 基礎スピードを着順や終いの速さではなく、200mごとの巡航速度、馬群への接続、位置維持から評価
- レース内相対評価に必要な個別ラップを事前確認し、取得は最大2回再試行。なお不足する場合は能力不足にせず未測定扱い
- 最高速度を「観測した絶対上限」と「今回の消耗後に発揮できる速度」へ二層化
- 逃げ馬判定を「先頭へ到達できる初速」と「実際に先頭を選ぶ再現性」へ分離
- 逃げ馬不在時は中盤の緩みを基本とし、ラップ上の明確な圧力がある場合だけ持続流へ変更
- 隊列を200mごとに更新し、枠、内外、コース形状、馬群接続を直線到達まで引き継ぐ
- 予想結果を変えないキャッシュと一括読込を導入し、代表ケースでは同一JSONのまま約97.6秒から41.4秒へ短縮

## ラップベース評価の工夫

基礎スピードを単純な着順や走破時計だけで判断せず、次の要素に分けて評価しています。

- 同条件の標準ペースに対して、各200m区間をどの速度で巡航したか
- 速い流れの中で、主馬群へ接続して位置を維持できたか
- 前受けで流れを直接受けたか、後方で脚を温存したか
- 距離変更時に、短距離の速さと長距離の巡航を同じ価値として扱っていないか
- 元データの欠損状況と、推定に依存した割合

各過去走には `MEASURED`、`ESTIMATED`、`NOT_TESTED` の状態と信頼度を付けます。最終評価では、証拠強度の高い最大5走を重み付きで集約し、中心値だけでなく上下限も保持します。

最高速度は一つの点数だけで予想へ直接入れません。観測した絶対最高速は能力値として保持し、展開、馬場、隊列から直線入口までの負荷を計算して、余力―速度曲線から今回の発揮値を求めます。これにより、高い最高速を持つ馬でも追走で消耗した場合は、その全てを発揮できないと表現できます。

```mermaid
flowchart LR
    A[外部データ] --> B[Collector]

    D --> E[Analysis Snapshot]

    M --> K[最終予想順位]
```

## 公開版の実行方法

Python 3.11以上を想定しています。公開デモは標準ライブラリだけで動作します。

```bash
python -m unittest discover -s tests -v
python examples/run_demo.py
python scripts/check_public_safety.py
```

`examples/run_demo.py` は架空データのみを使用し、基礎スピード、馬場・流れ、最高速度の発揮値、逃げ馬判定をJSONで表示します。公開コード内の係数は設計レビュー用の代表値であり、本番DBから較正した係数や収集データは含みません。
