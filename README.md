# Keiba Analyzer — 競馬予想AI（開発中）

> 競馬予想に含まれる感覚的な判断を、再現可能なデータ処理・能力評価・信頼度管理へ落とし込む個人開発プロジェクトです。

**現在開発中です。** データ基盤、説明可能な能力評価、馬場分析、区間展開・隊列予測、位置別能力要求、道中負荷と直線到達を一つの予想エンジンへ接続しています。

2026-09-18に、実際に稼働中のWebアプリの版を確認して公開内容を同期しました。公開版は設計・代表コードであり、アプリ本体の複製ではありません。[同期範囲と未反映の開発内容](docs/deployed_sync.md)を区別して記録しています。

本リポジトリは採用ポートフォリオ向けの公開版です。Private版から、個人情報・認証情報・収集済みデータ・外部サイト固有の取得処理を除外し、設計と代表ロジックが伝わる形に再構成しています。

## 解決したい課題

競馬予想では、馬場、展開、追走力、最高速度、スタミナなど多くの要素が絡み、判断基準が曖昧になりやすいという課題があります。そこで、次の流れを一つの分析基盤として構築しています。

- 2020年以降の中央競馬全レースを収集対象としてデータを蓄積
- 出走情報、過去走、通過順、上がり3F、レースラップ、個別ラップを正規化
- 馬の主要能力と補助適性を分離し、各過去走を0〜10点で評価
- 欠損データを無理に平均値で埋めず、信頼度と評価状態を併記
- 採点根拠を保存し、結果を後から検証できるようにする
- 当日の馬場、区間展開、予想隊列から馬ごとに異なる能力配分を生成
- 4角位置と残存余力だけでなく、直線で実際に追い抜けるかを計算
- 能力ロジックごとの入力指紋で、変更のあった能力だけを安全に再計算
- ログイン単位で状態を分離し、複数レースの予想ジョブを並行実行

## 能力評価の設計

主要能力は次の5項目です。

| 項目 | 評価の主眼 |
|---|---|
| 基礎スピード | 巡航速度と追走力 |
| 最高速度 | 終盤で到達できる速度 |
| ギアチェンジ | 短い区間で急加速する力 |
| ロングスパート | 高い速度を長い区間維持する力 |
| スタミナ | ペース・距離・位置による消耗後も速度を残す力 |

補助適性として、低グリップ適性、坂適性、重馬場適性、小回り適性、持ち時計上限を使います。1200mも距離別基準のロングスパートを使い、独立したスプリント性能には置き換えません。

公開版では、現行の**共通展開・ラップ時計の契約**を純粋関数として掲載しています。逃げ馬・位置別能力要求の簡略例と、基礎スピード・余力曲線の過去の設計例も残していますが、これらの簡略係数は現行アプリの採点式や較正値ではありません。

## 直近の設計更新

- 能力値・棒グラフの最高速は、対象距離に対応する絶対能力値を使用。道中負荷による発揮低下は直線到達モデルが担当し、能力値を事前に二重減衰させない
- 表示、位置別能力要求、直線モデルへ同じ馬場・能力値・決定済み展開を渡す
- コースの事前想定が5Fでも、決定済み展開が3Fなら3Fを使う。直線以降には実際に残る区間距離だけを渡す
- 1500m・1700mなどの最初の100mを200mとして倍算せず、次区間と合わせた実距離で時計を推定。補間値は実測値と区別
- 基礎スピードは巡航だけでなく全体の流れと終盤失速も確認。スタミナのL2・最終1Fは別々に確認し、負荷と能力を二重に割り引かない
- 個別ラップの不足確認・再取得、SQLite書き込み競合、開催日取得を修正
- 時系列バックテストで予想上位5頭の三連複BOXなどを評価。取得失敗・評価不能・不的中を混同しない

## ラップベース評価の工夫

基礎スピードを単純な着順や走破時計だけで判断せず、次の要素に分けて評価しています。

- 同条件の標準ペースに対して、各200m区間をどの速度で巡航したか
- 速い流れの中で、主馬群へ接続して位置を維持できたか
- 前受けで流れを直接受けたか、後方で脚を温存したか
- 距離変更時に、短距離の速さと長距離の巡航を同じ価値として扱っていないか
- 元データの欠損状況と、推定に依存した割合

公開用の旧採点例では `MEASURED`、`ESTIMATED`、`NOT_TESTED` と上位5走集約を示しています。現行アプリでは能力ごとに証拠採用・距離移送・集約方法が異なるため、この例を全能力共通の本番採点式として扱いません。欠損による未測定と、ラップから確認できた追走失敗も区別します。

最高速度の能力値は直線モデルまでそのまま渡します。直線モデルで基礎スピード・スタミナ、累積負荷、位置差、加速、馬場条件を使って発揮可能性を計算します。公開している旧 `max_speed_expression.py` の余力曲線は設計履歴であり、現行アプリで能力点を予想前に書き換える処理ではありません。

## アーキテクチャ

```mermaid
flowchart LR
    A[外部データ] --> B[Collector]
    B --> C[Parser / Normalizer]
    C --> D[(SQLite Raw Tables)]
    D --> E[Analysis Snapshot]
    E --> F[摩擦 / グリップ / 時計]
    E --> G[主要5能力 / 補助適性]
    F --> H[序盤 / 中盤 / 終盤の展開]
    G --> I[位置別能力要求]
    H --> I
    I --> J[実距離の隊列 / 逃げ馬判定]
    J --> L[位置差 / 道中負荷 / 4角余力]
    G --> M[直線内の発揮速度 / 到達可否]
    L --> M
    M --> K[直線評価を一度接続した最終得点 / 順位]
```

設計の詳細は [`docs/architecture.md`](docs/architecture.md) に記載しています。

## 公開版の実行方法

Python 3.11以上を想定しています。公開デモは標準ライブラリだけで動作します。

```bash
python -m unittest discover -s tests -v
python examples/run_current_contract.py
python scripts/check_public_safety.py
```

`examples/run_current_contract.py` は架空の1700m戦で、展開区間の共有と100m端数を含む時計を表示します。DB・通信・認証は不要です。旧 `examples/run_demo.py` と `sample_analysis_output.json` は過去の簡略採点例として保持しています。どちらも実馬の能力値・本番の予想精度を再現するデモではありません。
